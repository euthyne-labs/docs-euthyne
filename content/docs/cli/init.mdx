<Callout title="Preview">Flags may change.</Callout>

```bash
# signs you in through your browser on the first run, then enrols each further repository
euthyne init

# or sign in with a one-time enrolment token from your admin
euthyne init --token-stdin < enrol-token.txt

# hooks for every project, recording every repository of your GitHub organization
euthyne init --hooks user --enrol 'github.com/your-org/*'

# record Codex as well as Claude Code in this repository
euthyne init --agent claude-code --agent codex
```

Run it inside a git repository. Outside one, it stops with an error.

## What it does

1. Shows what Euthyne records and what it never records, with one more paragraph for each agent other than Claude Code you pick with `--agent`, then asks you to type `yes` on your terminal. If you do not, it stops: nothing is installed and nothing is recorded.
2. Creates this machine's device key in your OS keychain, or reuses the one it has.
3. On the first run, signs this machine in through your browser, or with a one-time enrolment token. Your acceptance (the consent text version and the time) is sent with the enrolment. If the machine is already signed in, for example with [`login`](/docs/cli/login), it sends your acceptance to the server instead.
4. Enrols the current repository.
5. Asks where the hooks go, then installs them for each agent, in this repository or in your user settings. See [Hooks it installs](#hooks-it-installs).
6. When Claude Code is one of the agents, asks whether it may add Claude Code telemetry lines to your user settings, for tokens and cost. See [Tokens and cost](#tokens-and-cost).
7. Prints a summary and a preview of the [mandate](/docs/concepts/mandates) your sessions will record.
8. Signs a test receipt and starts uploading it in the background. The output links to it on the dashboard, where it shows once uploaded.

Signing in opens `app.euthyne.com` in your browser. Type the code the terminal shows, approve, and pick the organization. With `--no-browser`, `init` prints the link instead.

Running `init` again in the same repository changes nothing that already exists. It does not add duplicate hooks. It signs a new test receipt each time.

## The consent text

This is what `init` prints before it asks, for Claude Code. `<server>` is the server you enrol with, `https://api.euthyne.com` by default. Each other agent you pick adds a paragraph that lists its hook events, the permission settings read for its mandate, where its tokens come from, and any trust step it needs.

```text
Euthyne records what Claude Code does in the repositories you enrol, so you can prove it later.

Recorded on this machine, signed, and sent to <server>:
  - harness, model, your Euthyne user ID, repo remote, branch, commits, timestamps
  - each tool call: tool name, MCP server and tool names, outcome, duration, file paths, git blob SHAs
  - web research: the domain in clear; full URLs and search queries only as salted hashes
  - the permission mode, your Claude Code permission rules (allow, ask, deny), MCP server names and
    sandbox settings, and whether each action was inside them
  - tokens, cost and API time, from Claude Code's telemetry

Never sent, kept on this machine only as salted hashes or not at all:
  - prompts, tool inputs and outputs, file contents, diffs, transcripts
  - settings env blocks, API keys and key helpers, MCP server commands, URLs, headers and env
  - every telemetry attribute other than tokens, cost, duration, model and session ids

To read tokens and cost, init then asks to add Claude Code telemetry lines to your user settings
(~/.claude/settings.json), exported only to an authenticated receiver on 127.0.0.1. Skip it with --no-otel.

Consent text version 2026-10-12.
```

You accept by typing `yes` on your terminal. `init` reads the answer from the terminal, not from stdin, so a pipe or a script cannot answer for you. `--yes` does not accept it. Without a terminal, `init` stops, unless you pass `--accept-recording`.

Only pass `--accept-recording` when you are the person accepting and you have read the terms. It records your consent, not someone else's. The terms are still printed, with a warning that you accepted them by flag.

The acceptance is per organization and per text version. When the text changes, the next `init` asks again.

## Tokens and cost

Claude Code reports tokens and cost through OpenTelemetry, not through hooks. After the hooks question, `init` asks:

```text
Add usage telemetry to your user settings? This applies to all your Claude Code sessions. Euthyne only keeps usage for repos you enrolled.
```

If you type `yes`, it adds lines to the `env` block of your user settings (`~/.claude/settings.json`, or the one under `CLAUDE_CONFIG_DIR`):

- `CLAUDE_CODE_ENABLE_TELEMETRY`, `OTEL_LOGS_EXPORTER` and `OTEL_METRICS_EXPORTER`, to turn the export on.
- The OTLP protocol, endpoint and headers for logs and metrics, pointing at a receiver on `127.0.0.1` only, with a bearer secret unique to your install.
- Two short export intervals.

Before it writes, it saves a copy of your settings file, readable only by you. [`uninstall`](/docs/cli/uninstall) removes exactly these lines and deletes the copy.

The receiver is `euthyne otel`. Hooks start it when needed. It keeps only tokens, cost, duration, model and session IDs, drops every other attribute, and exits 30 minutes after your last session. It only keeps usage for sessions in enrolled repositories. The lines apply from the next time you start Claude Code.

If your user settings already set an OpenTelemetry endpoint, protocol or headers, `init` leaves them as they are and records no tokens or cost. If the default port is taken by another program, it picks a free one.

## Flags

| Flag | Effect |
| --- | --- |
| `--server <url>` | Euthyne API base URL. Also `EUTHYNE_SERVER`. Defaults to the server this machine enrolled with, else `https://api.euthyne.com`. Must use `https` |
| `--no-browser` | Prints the sign-in link instead of opening a browser |
| `--token-stdin` | Reads a one-time enrolment token from the first line of stdin, instead of signing in through the browser |
| `--token <token>` | Passes the token as an argument. Avoid it: the token lands in your shell history and process list, and `init` warns you |
| `--agent <name>` | Agent to install the hooks for: `claude-code` (default), `codex`, `cursor`, `grok-build`, `copilot`, `opencode`, `devin-desktop`, `gemini-cli`, `antigravity` or `hermes`. Repeatable. See [Supported agents](/docs/agents) |
| `--hooks <where>` | Where the hooks go: `repo` or `user`. Asked when not set. See [Hooks it installs](#hooks-it-installs) |
| `--enrol <pattern>` | Also records every repository whose origin remote matches the pattern. Repeatable. Implies `--hooks user`. See [Which repositories are recorded](#which-repositories-are-recorded) |
| `--accept-recording` | Accepts the recording terms without a terminal prompt. The terms are still printed |
| `--yes` | Answers the setup questions without a prompt: adds the telemetry lines, and installs the hooks in the repository unless `--hooks` says otherwise. Does not accept recording |
| `--no-otel` | Does not touch your user settings for telemetry. No tokens or cost are recorded |
| `--otel-port <port>` | Port of the local receiver on `127.0.0.1`. Default `47318` |
| `--rotate-otel` | Replaces the receiver's bearer secret in your user settings |
| `--json` | Prints one JSON object on stdout, with the test receipt's ID, session and dashboard link. Everything else goes to stderr |

The enrolment token can also come from the `EUTHYNE_ENROL_TOKEN` environment variable. It enrols one machine. Keep it out of your shell history.

The questions are asked on your terminal, not read from stdin, so `--token-stdin` works with them: `euthyne init --token-stdin < enrol-token.txt` still asks you.

## Hooks it installs

For Claude Code, one entry per event, each running `euthyne hook claude-code`:

`SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionDenied`, `SubagentStart`, `SubagentStop`, `Stop` and `SessionEnd`.

The `PreToolUse` entry carries `onFailure: "block"`, so that under an enforced [org policy](/docs/concepts/policy) a crash or a timeout of the hook blocks the call. Without an org policy, it returns at once and records nothing.

The hooks of the other agents, their files and their trust steps are listed in [Supported agents](/docs/agents).

For Claude Code, they go in one of two places:

- `repo`: `.claude/settings.local.json` in this repository. `init` adds that file to `.git/info/exclude`, so it is never committed by accident.
- `user`: your Claude Code user settings (`~/.claude/settings.json`, or the one under `CLAUDE_CONFIG_DIR`), so the hooks run in every project. Before it writes, `init` saves a copy of that file, readable only by you. It writes through a symlink and rewrites the file as JSON indented with two spaces; when that changes its formatting, `init` warns you and the copy keeps your version. [`uninstall`](/docs/cli/uninstall) deletes the copy.

Pick one with `--hooks repo` or `--hooks user`. Without `--hooks`, `init` asks:

```text
Install the Claude Code hooks in your user settings (~/.claude/settings.json) so they run in every project? Only enrolled repositories are recorded either way.
Type yes for every project, anything else for this repository only:
```

With `--yes`, or without a terminal, it does not ask and uses `repo`. Once the hooks are in your user settings, later runs keep them there. `--enrol` implies `user`.

If the same hook is in both files, Claude Code runs it once. Your other hooks and settings are kept as they are.

## Which repositories are recorded

Wherever the hooks are, only sessions in enrolled repositories are recorded. A repository is enrolled when:

- you ran `euthyne init` in it, or
- its origin remote matches a pattern you gave with `--enrol`.

A pattern is a host and a path, with no scheme or user, for example `github.com/your-org/*`. Case does not matter. `*` matches within one path segment, so `github.com/your-org/*` matches `git@github.com:your-org/api.git` and `https://github.com/your-org/api`, but not `github.com/your-org/team/api`. Pass `--enrol` more than once for several patterns. Remove one with [`uninstall --enrol <pattern>`](/docs/cli/uninstall), or all of them with `uninstall --all`.

Once a session has been in an enrolled repository, it stays recorded if it moves to a directory outside any git repository. Its receipts from there carry no repository, branch, commits or file paths. Its actions inside another repository that is not enrolled are not recorded.

Sessions anywhere else are not recorded at all: no receipt and no mandate.
