---
title: euthyne hook
description: Called by Claude Code to sign a receipt for one hook event.
---

<Callout title="Preview">Built for Claude Code, not publicly released yet.</Callout>

```bash
euthyne hook claude-code
```

You do not run this yourself. [`init`](/docs/cli/init) registers it in `.claude/settings.local.json`, and Claude Code calls it on each hook event.

On each call it:

1. Reads the hook event JSON on stdin.
2. Commits the whole payload, and each content field, as salted hashes.
3. Captures the session's [mandate](/docs/concepts/mandates) if it is the first event of the session, or signs a new version if the permission mode or a settings file changed.
4. Checks the action against the mandate in force: in, out or unknown.
5. Signs an action receipt with the session key.
6. Appends it to the local queue and exits.

It never touches the network. Receipts wait in the queue until you run [`sync`](/docs/cli/sync).

If telemetry is set up, the hook also starts the local OpenTelemetry receiver when it is not running. It never waits for it.

## When it records nothing

Without an enrolled device, or without your accepted consent for this organization, it exits at once and records nothing. An admin who installs the hooks for you cannot turn recording on. Only you can, with `init`.

## It never steers the agent

The hook writes nothing to stdout, so nothing reaches the agent's context. It does not use `PreToolUse`, so it can never block a tool call. The agent is never told its mandate.
